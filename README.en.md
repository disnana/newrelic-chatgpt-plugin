# New Relic × ChatGPT

Unofficial, self-hosted integration by Disnana. Each user creates an owner-only ChatGPT Site and connects the Plugin generated by that Site. This repository distributes source, not an importable Plugin ZIP.

[Japanese README](README.md) · [Setup](docs/setup.md) · [Security limitations](docs/security-review.md)

## Setup

1. Download the setup ZIP and checksums from [Releases](https://github.com/disnana/newrelic-chatgpt-plugin/releases/latest). No downloadable Release exists before the first approved tag.
2. Use a ChatGPT account with Sites, Worker, D1 and MCP support. Enable New Relic MCP access and the required organization read permissions.
3. Attach the source ZIP to ChatGPT Sites and request a new owner-only Site. Configure the DB binding, all four migrations, MCP capability, and an independently generated 32-byte base64url encryption key in the Site secret `NEW_RELIC_TOKEN_ENCRYPTION_KEY`. Never expose that key in chat or source.
4. Publish the Site owner-only and connect its generated Plugin. Select the New Relic region and complete OAuth. Paste the full localhost callback URL only into the Site's completion page, never into chat.
5. In the Site's “Usage category permissions” section, select the read categories you want and save. Core reads are off by default. Core Compute metering does not by itself establish an extra charge; whether usage is included or billed separately depends on the account's billing model, which this integration cannot inspect. Advanced AI tools use Advanced Compute (aCCU) separately and require the matching contract or trial. Permissions expire after 30 days and can be revoked at any time. Then select an account and use the generated Plugin. Disconnect through the Site when finished; revoke New Relic OAuth consent separately if required.

A full fresh-user installation has not been verified. See the Japanese setup guide for the exact setup prompt and troubleshooting. Sites availability depends on the user's account and environment.

## Development

Requires Node.js 22, Python 3 and bash. No external credentials are needed for mock tests.

```sh
npm ci
npm run build
npm run validate
npm run typecheck
npm run lint
npm test
npm audit --audit-level=high
python3 scripts/test-migrations.py
python3 scripts/check-distribution.py
python3 scripts/package-release.py v0.4.0
```

CI runs on branch pushes and PRs. Only a change to `VERSION` pushed to main triggers tagging and Release creation after checks pass. Review before merging a version change.

## Security

Owner-only personal deployments are intended. OAuth state/PKCE, encrypted token storage, refresh leases, same-origin checks, bounded responses and conservative NRQL restrictions have mock coverage. Production concurrency, lease expiry, separate real-user isolation, full NRQL syntax and fresh mobile installation remain unverified. Never upload tokens, callback URLs or real telemetry to issues. Secret-pattern scanning is not a complete secret detector.

## v0.4.0 development status

OAuth failure classification, a fail-closed schema-pinned generic MCP adapter, expiring per-user consent for Core/Advanced/Preview reads, and an opt-in signed-assertion verifier for an external self-host gateway are implemented. A separate gateway boundary reference is included, but it requires operator-supplied browser/MCP authentication and CSRF adapters and is not a login service or production-ready multi-user gateway. This is **not full official MCP parity**. The documented inventory contains 41 tools, but authenticated live schemas and new runtime execution remain unverified (0 live-verified generic tools). Core and Advanced reads stay off until the user selects them in the Site. Core CCU metering does not by itself prove an extra charge; the integration cannot inspect the account billing model. Advanced Compute is separate and needs the matching entitlement or trial. Generic reads also require a pinned policy and matching per-user consent. Write and destructive operations remain disabled because per-operation user approval is not implemented. The default identity mode remains ChatGPT Sites; self-host assertion mode and the wrapper are locally mocked only and must remain behind an independently reviewed gateway.

See [migration and policy setup](docs/v0.4.0-migration.md), [self-host auth boundary](docs/self-host-auth.md), [gateway reference](examples/self-host-gateway/README.md), [operation approval design](docs/operation-approval-design.md), [official feature research](docs/official-mcp-research.md), [OAuth](docs/oauth.md), and [security review](docs/security-review.md). No production deployment is included.
