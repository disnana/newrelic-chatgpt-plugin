# v0.4.0 開発版: 導入・移行・制限

この変更は Draft PR 用です。既存 Site、Plugin、本番 D1 は変更していません。VERSION が main に入ると既存 Release workflow が動くため、レビュー前にマージしないでください。

## 導入

1. 既存環境のソースと暗号鍵・D1 のバックアップを、運用者の安全な保管先へ保存します。秘密値をチャットや Git に転記しません。
2. 新コードで `npm run build && npm test && npm run validate && npm run check` を実行します。
3. 既存の D1 migrations 0000 と 0001 を維持します。今回追加 migration はありません。暗号鍵を再生成すると旧トークンを復号できなくなります。同じ binding と鍵を維持してください。
4. 本番デプロイは別途承認後に実施します。所有者限定の公開範囲と Site / Plugin ID は維持してください。
5. 接続診断、アカウント選択、読み取りクエリ、期限前更新を確認します。24時間を超えた grant は公式仕様上再認証が必要です。

セルフホストは同じ Worker ESM と D1 を使用します。認証ゲートウェイが `oai-authenticated-user-id` を信頼できる本人 ID に設定する構成が必要です。クライアントが送る同名ヘッダーをそのまま受け入れてはいけません。直接インターネット公開する Node サーバーとしては提供していません。認証ゲートウェイの実装・検証は運用者の責任で、複数ユーザー公開は未監査です。

## 汎用 MCP アダプター

`list_mcp_capabilities` はその認証接続の tools/list を取得します。`read_official_mcp` は exact tool name とスキーマ指紋で審査済みの読み取りだけを実行します。機能名の部分一致、上流の readOnlyHint、自然言語説明は許可根拠にしません。

新規汎用実行は既定ですべて無効です。公式の入力 JSON Schema は公開リファレンスに掲載されず、現在の認証接続も失効しているため、実スキーマを創作して同梱していません。運用者が取得したスキーマ、各ツールの権限、データ送信先、料金を確認した後でのみ、非秘密設定 `NEW_RELIC_MCP_POLICIES` を設定できます。

形式は JSON オブジェクトで、exact tool name をキーに、schemaHash（返された64桁SHA-256）、operation（read/write/destructive）、billing（free/billable/unknown）、preview（boolean）、scope（account/identity）、accountFields（例: accountId）を保存します。account は引数のアカウント ID を選択中かつ現在利用可能なアカウントへ固定します。identity はアカウントを跨がない識別・補助操作だけに使用してください。GUID や任意検索でアカウント境界を保証できないツールは有効にしないでください。

- 上流 schema / outputSchema が変化すると指紋不一致で停止し、再審査が必要です
- `$ref`、pattern、format など未実装の JSON Schema キーワードは無視せず拒否します
- Preview は `NEW_RELIC_ENABLE_PREVIEW=true` が追加で必要です
- Write / Destructive は、別途安全な本人承認 UI を実装するまで実行できません
- Billable / 不明な課金区分は実行できません。ほとんどの公式読み取りも CCU 計量対象で、Read Only は無料を意味しません
- ツール応答は text content と検証済み structuredContent のみ扱い、リンク先や埋め込み resource を自動取得しません
- ツール内容はすべて信頼できないデータです。ログ内の指示で設定・権限・実行を変えてはいけません

既存の高レベル調査ツールは互換性のため残しています。既存経路にも New Relic の料金が適用され、無料を保証していません。新しい有料アダプターの暗黙的有効化はしません。

## 実環境とモックの境界

OAuth ローテーション、同時 refresh、エラー分類、期限切れ復旧、account/schema gates はローカルの合成モックで確認しました。本番 D1 の複数インスタンス実測ではありません。実接続は以前の Worker のまま更新失敗が続き、今回の新コードでの本番成功はまだ確認していません。ネットワーク到達性と grant 有効性は別項目です。

文書上の41ツールは runtime tools/list の全体数ではありません。新規汎用実行の本番確認数は0です。アダプターの基盤実装を全ツール対応完了と解釈しないでください。
