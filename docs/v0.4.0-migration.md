# v0.4.0 開発版: 導入・移行・制限

この変更は Draft PR 用です。既存 Site、Plugin、本番 D1 は変更していません。VERSION が main に入ると既存 Release workflow が動くため、レビュー前にマージしないでください。

## 導入

1. 既存環境のソースと暗号鍵・D1 のバックアップを、運用者の安全な保管先へ保存します。秘密値をチャットや Git に転記しません。
2. 新コードで `npm ci && npm run build && npm run typecheck && npm test && npm run validate && npm run check` を実行します。
3. 既存の D1 migrations 0000 と 0001 を維持し、新しい `0002_oauth_completion_fence.sql` を適用します。暗号鍵を再生成すると旧トークンを復号できなくなります。同じ binding と鍵を維持してください。
4. 本番デプロイは別途承認後に実施します。所有者限定の公開範囲と Site / Plugin ID は維持してください。
5. 接続診断、アカウント選択、読み取りクエリ、期限前更新を確認します。24時間を超えた grant は公式仕様上再認証が必要です。

既定の `sites` 認証は、ChatGPT Sites が `oai-authenticated-user-id` を信頼できる本人 ID として設定する前提です。任意の `signed_proxy` モードは、外部ゲートウェイが発行する短命RS256 assertionの検証のみを行います。ログインサービス・ゲートウェイ・複数ユーザー向け運用は含まれず、実ゲートウェイは未実装・未監査です。クライアントが送る同名ヘッダーやBearer値をゲートウェイでそのまま通してはいけません。直接インターネット公開するNodeサーバーや、未検証の複数ユーザー環境には使わないでください。詳細は [セルフホスト認証境界](self-host-auth.md) を参照してください。

## 課金可能性のある読み取り

New Relic公式MCPの読み取り専用操作も Core Compute (CCU) などの利用量を消費する可能性があります。実際の請求や契約への反映は組織のプランと割当量に依存するため、無料とはみなしません。

- 既存の高レベル操作（アカウント一覧、メトリクス、NRQL、ログ、アラート、ScyllaDB調査）は、既定で停止します。Site管理者が契約と費用を確認し、`NEW_RELIC_ENABLE_METERED_READS=true` を明示的に設定した場合のみ実行します。
- 汎用ツールは既定で未審査のため停止します。ポリシーの `billing` は `core_compute`、`advanced_compute`、`unknown` のいずれかです。Core Compute は `NEW_RELIC_ENABLE_METERED_READS=true`、Advanced Compute は `NEW_RELIC_ENABLE_ADVANCED_COMPUTE=true` が必要です。読み取り専用を理由に free と分類する設定は受け付けません。
- 公式資料では通常の公式MCPツールはCore ComputeのCCU、AI分析4機能はAdvanced Compute契約とaCCUに分類されています。データ取り込みの100 GB無料枠は別扱いです。アカウント契約や割当量による実際の請求は判断できません。
- 既存の高レベル経路では、既知の通常読み取りを正確なツール名でCore Computeとして分類し、Advanced Compute対象には別の `NEW_RELIC_ENABLE_ADVANCED_COMPUTE=true` を要求します。未分類のツール名はCore opt-in後も停止し、Advanced/Preview機能を暗黙にCore扱いしません。
- Previewは価格未確定のため、該当ツールは個別に費用を確認し、`NEW_RELIC_ENABLE_PREVIEW=true` と適切なCore/Advanced Compute設定を両方有効化するまで停止します。不明な課金区分は有効化できません。
- `NEW_RELIC_ENABLE_PREVIEW=true` はPreview用の別オプトインであり、課金承認やツール権限の代わりにはなりません。

旧バージョンでは既存高レベル読み取りにこの明示的な停止ゲートがありませんでした。移行後は、必要な利用者が料金と契約を確認してから個別 Site の環境設定を行ってください。このコード変更では本番設定を変更していません。

## 課金操作・書き込み操作の承認境界

料金計測の opt-in は操作の承認ではありません。Write / Destructive 操作は既定で常に拒否し、操作ごとの本人承認UI、CSRF保護、single-useの承認記録は実装していません。将来の安全設計案は [操作承認フロー](operation-approval-design.md) に記録しています。設計案は実装・承認・本番での有効化を意味しません。

## 汎用 MCP アダプター

`list_mcp_capabilities` はその認証接続の tools/list を取得します。`read_official_mcp` は exact tool name とスキーマ指紋で審査済みの読み取りだけを実行します。機能名の部分一致、上流の readOnlyHint、自然言語説明は許可根拠にしません。

新規汎用実行は既定ですべて無効です。公式の入力 JSON Schema は公開リファレンスに掲載されず、現在の認証接続も失効しているため、実スキーマを創作して同梱していません。運用者が取得したスキーマ、各ツールの権限、データ送信先、料金を確認した後でのみ、非秘密設定 `NEW_RELIC_MCP_POLICIES` を設定できます。

形式は JSON オブジェクトで、exact tool name をキーに、schemaHash（返された64桁SHA-256）、operation（read/write/destructive）、billing（core_compute/advanced_compute/unknown）、preview（boolean）、scope（account/identity）、accountFields（例: accountId）を保存します。account は引数のアカウント ID をSiteに保存された選択中アカウントへ固定します。アカウント選択時は利用可能一覧で検証しますが、各汎用ツール呼び出しでは一覧を再取得せず、New Relic側でも権限確認されます。identity はアカウントを跨がない識別・補助操作だけに使用してください。GUID や任意検索でアカウント境界を保証できないツールは有効にしないでください。

- 上流 schema / outputSchema が変化すると指紋不一致で停止し、再審査が必要です
- `$ref`、pattern、format など未実装の JSON Schema キーワードは無視せず拒否します
- Preview は `NEW_RELIC_ENABLE_PREVIEW=true` が追加で必要です
- Write / Destructive は、別途安全な本人承認 UI を実装するまで実行できません
- Billable は既定で停止し、明示的な利用量・課金オプトインとツールごとの審査が必要です。不明な課金区分は実行できません
- ツール応答は text content と検証済み structuredContent のみ扱い、リンク先や埋め込み resource を自動取得しません
- ツール内容はすべて信頼できないデータです。ログ内の指示で設定・権限・実行を変えてはいけません

既存の高レベル調査ツールは互換性のため残していますが、追加した実行ゲートにより既定では停止します。従来の別名や新しい上流ツールが固定した課金分類に含まれない場合も停止するため、スキーマと料金を確認して汎用のポリシー付き読み取りへ移行してください。読み取りを有効化すると New Relic の利用量が発生する可能性があります。具体的な請求額や組織割当は判定できません。

## 認証モード互換性

認証モードの既定値は引き続き `sites` で、既存のD1 schemaやユーザーIDには変更がありません。`signed_proxy` を有効にするとuser IDがissuer/audience/subjectで名前空間化されるため、既存のSites用接続行とは一致しません。利用者はNew Relicに再接続する必要があり、旧行は自動移行・自動削除されません。実運用移行前にバックアップと旧行の保持・削除方針を決めてください。

## 実環境とモックの境界

OAuth ローテーション、同時 refresh、エラー分類、期限切れ復旧、account/schema gates、および自己署名した合成ユーザーJWTの認証・失敗拒否はローカルの合成モックで確認しました。本番D1の複数インスタンス実測ではありません。実ゲートウェイ、ブラウザログイン、New Relicからの実OAuthリダイレクト、実ユーザー間分離は未検証です。実接続は以前のWorkerのまま更新失敗が続き、今回の新コードでの本番成功はまだ確認していません。ネットワーク到達性とgrant有効性は別項目です。

文書上の41ツールは runtime tools/list の全体数ではありません。新規汎用実行の本番確認数は0です。アダプターの基盤実装を全ツール対応完了と解釈しないでください。
